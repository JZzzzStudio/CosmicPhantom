# requirement-clarify.md — 拷问式需求澄清（门禁第 10 条详细规则）

> 配套：reply-policy.json 第 10 条（一句话触发）+ 项目级 CONTEXT.md（领域共享语言）
> 优先级：与回复门禁同级。适用场景：需求/设计/方案类对话；普通问答、闲聊、执行类指令不启用。

## 核心纪律

1. **先读档再提问**：进入需求对话，先找并读项目 CONTEXT.md；没有就建空模板，告知用户"我会边聊边建"。
2. **用共享语言说话**：提问与回答必须使用 CONTEXT.md 已定义术语；发现术语冲突当场指出，不得含糊带过。
3. **按规模选提问模式**：小需求每轮最多 1-2 个关键问题，优先问影响最大的；大设计（≥3 个相互依赖的决策）用「设计树 + 前沿轮」（见下），一轮问完整条前沿。两种模式都不许猜用户答案。
4. **给选项、给推荐、讲理由**：每个问题给 2-3 个具体选项 + 推荐 + 理由，让用户做选择题，不做填空题。
5. **边聊边写**：每达成一个共识立即更新 CONTEXT.md；决策记录由决策卡同步器（decision-cards.js）从 daily 自动承载，无需手写 ADR 文件（ADR 机制已废除，用户 2026-08-12 决定）。
6. **不重复提问**：文档已定义的术语直接使用，不再追问。

## 大设计模式：设计树 + 前沿轮（2026-10-28 吸收 grilling）

适用：≥3 个相互依赖的决策、跨天/跨模块、需要先定架构再动手。

1. 把设计拆成决策树；**前沿** = 所有前置已定的问题，也就是现在就能问、不必猜的。
2. **一轮问完整个前沿**：每题编号 + 推荐答案 + 理由；等用户答完再算下一轮。
3. **事实自己查**（文件/工具/检索），不向用户要；只有决策交给用户。
4. 前沿为空 = 结束；请求用户确认「可以写规格了」，再进 `core/workflow.md` 的②段。

格式：

```text
❓ Q1 - <问题标题>：<问题正文，可含选项>
➡️ <推荐答案与理由>
```

纪律：不问已知答案；不把事实问题伪装成决策问题；哪个问题的答案依赖本轮另一个未决问题，它就属于下一轮。

## 四阶段流程

### 阶段一：开机读档
- 搜索项目 CONTEXT.md（大项目可按领域多个）
- 读取后一句话复述关键术语，确认后开始

### 阶段二：拷问（每个想法循环四步）
- 第 1 步 对质术语：用户话里每个词与术语表对质，用法不一致当场指出（"术语表里'用户'指已注册有登录凭证的人，你指的是匿名访客吗？新增术语还是改定义？"）
- 第 2 步 精炼歧义：追问到无歧义（手动还是自动？单向还是双向？实时还是定时？1:1 / 1:N / N:M？）
- 第 3 步 边界测试：空值允不允许？删除 X 时关联 Y 怎么办（置空/级联/限制）？极端情况（空列表/重复/并发）？
- 第 4 步 收口写回：确认后立即更新 CONTEXT.md；决策行由决策卡同步器自动收录

### 阶段三：记录
- CONTEXT.md 定义格式（声明式无歧义）：
  - 术语：X / 定义：……
  - 关系：……
  - 业务规则：……
- 决策记录：由决策卡同步器（decision-cards.js 自动管道）从 daily「⭐👤 用户（决策）」行逐字生成记忆卡；不再手写 ADR 文件（2026-08-17 定，原 ADR 触发条件/格式/路径全部废止）

### 阶段四：收敛（全部满足才结束）
- 所有术语已定义且无冲突
- 所有关系已明确数量级
- 主要边界情况已确认
- 与现有规则无矛盾
- 结束输出"共识摘要"（新增/修改的术语和决策），请用户确认

## 提问话术库

- 数量关系："X 和 Y 是什么数量关系？A) 1:1 B) 1:N C) N:M。我推荐 B，因为……"
- 术语冲突："A) 保留原定义细分出子类；B) 重新定义新建对等术语。我推荐 A，因为这两个维度正交……"
- 状态："状态是手动改还是按时间自动计算？只能按顺序跳还是任意跳？"
- 删除语义："删除 X 时 Y 怎么办？A) 置空 B) 级联删除 C) 限制删除。我推荐 A，因为……"
- 空值边界："标题和描述可以为空吗？我推荐标题必填，为空时默认叫'无标题'。"

## 输出风格

- 简洁：使用共享术语后解释应明显变短，能一句话说清不用三段
- 结构化：选项用 A/B/C 列出，推荐与理由单独成行
- 不啰嗦：不重复已确认的定义，不复述用户刚说的话
