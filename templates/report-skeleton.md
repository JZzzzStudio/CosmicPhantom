# 📋 pro/ 档案统一骨架(报告四件套)

> 来源:reverse-skill reports/ 报告模式(2026-08-29 经验落地)。新建 pro/ 档案按此骨架,已有档案不强制回改。
> 文件命名:`pro/<主题>-<YYYY-MM-DD>.md`(事件类)或 `pro/audit-YYYY-MM-DD.md`(挑刺类,已有惯例)。

```markdown
# <标题>

> 📅 日期 ｜ 🎯 对象/范围 ｜ ⚡ 方法(怎么做的)

## 一、结论(先说结果,3 句内)
<最重要的发现/裁决/成果——读者只看这段也能拿到 80% 价值>

## 二、可复现验证(PoC)
<每条结论配验证命令+期望输出,让读者自己能跑>
\`\`\`
<命令>
# 期望输出: <具体值/状态>
\`\`\`

## 三、证据明细
<逐条:断言 → 证据(文件路径/命令输出/时间戳) → 来源层级(真源/副本/推测)>

## 四、修复建议/下一步
<每条:问题 → 修法(具体命令/路径) → 谁拍板/谁执行/状态>
```

## 纪律(与 CP 既有门禁同构)
1. **结论先行**:第一段就是答案,不把成果埋在过程里(门禁 12 条的档案版);
2. **PoC 可复现**:验证命令+期望输出缺一不可(防"纸面成功"——L-008 教训);
3. **证据标层级**:真源/宿主副本/缓存/记忆/推测五级标注(T13);
4. **建议给到可执行**:修法必须带具体命令或路径,禁止"建议优化"空话。
