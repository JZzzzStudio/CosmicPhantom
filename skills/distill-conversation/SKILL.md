# 🧪 对话蒸馏提纯（distill-conversation）

> 可复制、可搬运：本 skill 自包含全部规则，不依赖任何宿主平台特性。复制本目录到任意宿主的 skills 目录即可用；所有路径用 `<根>` 占位（= Cosmic Phantom 系统根），跨机改一处即可。

## 🎯 角色与目标
你是对话蒸馏师。输入是原始对话记录（可多段、多会话、含闲聊与噪音），
输出是一份「🧠 精华档案」：只保留有价值信息，去除无效内容，合并重复表述，
用 Emoji + 日期序号做视觉分层，让读者 30 秒内定位任意一条信息。

## 🧭 蒸馏四原则（优先级从高到低）
1. 🧹 **去噪**——无效对话一律剔除，宁缺毋滥
2. 🔗 **去重**——同一信息多次出现，只保留最完整的一条并合并出处
3. 📜 **保真**——不新增、不脑补、不篡改；矛盾信息必须保留并标为「待澄清」
4. 🗂️ **可检索**——每条精华带唯一编号与来源，可回溯原始会话

## 触发条件（全部满足才执行蒸馏；否则一句话说明跳过）

| # | 条件 | 检查方式 |
|---|---|---|
| 1 | 收工语义出现，或用户主动要求 | 对话中识别 |
| 2 | 距上次蒸馏 ≥7 天（`distilled/manifest.json` 的 lastRun；无 manifest 视为首次 → 执行） | 读文件 |
| 3 | 上次蒸馏后有新增事件（events.db 事件数 > lastRun 时计数；无则跳过） | 查询 events.db |

手动模式：用户指定会话/时间段 → 直接执行，不受 7 天限制。

## 📥 输入定位（只读）

- 默认：距上次蒸馏以来的全部 `events.db` 原始事件（`role=user` 原话，排除 `sensitive=1`），按会话分组
- 手动：用户指定的会话 ID / 时间段 / transcript 文件
- 参考：`daily/*.md` 的 `⭐👤 用户（决策）` 行、现有 `memories/` 与 `distilled/` 摘要（用于去重）
- 读取命令（任选可用者）：
  - `node --experimental-sqlite <根>/events.js status --root <根>`（确认范围）
  - `node --experimental-sqlite <根>/memory-cli.js events status --root <根>`（同义）
  - 直接 SQLite 只读查询亦可；**禁止任何写操作**

## 🧹 去噪规则（以下内容一律剔除）
- 寒暄客套：你好、在吗、谢谢、辛苦啦、哈哈、嗯嗯、好的收到
- 过程噪音：语气词、重复确认、改口前的废案、打字错误导致的重复
- 与主题无关的闲聊与跑题内容
- 已被后续消息明确推翻或撤回的旧表述
  （⚠️ 例外：若「推翻旧方案」这件事本身是重要决策，则保留决策本身）
- 无信息量的反馈：「可以」「没问题」「就这样吧」

## 🔗 去重规则（合并策略）
- 同一概念/需求被多次提及 → 合并为一条，取表述最完整、上下文最全的版本
- 同一决策被反复确认 → 只保留最终确认版，并同时标注首次提出时间与最终确认时间
- 合并时必须保留全部来源引用，格式：`会话X·第Y条` 或 `events.db:<instance>:<mid>`

## 📜 保真规则（红线，违反即失败）
- 严禁自行补充原文没有的信息
- 严禁把模糊表述「润色」成确定结论
- 发现矛盾信息 → 两条都保留，归入 ❓ 遗留问题，写明冲突双方
- 无法判断是否有效的信息 → 归入 ❓ 遗留问题，不擅自删除

## 🔖 编号规则
- 格式：`{蒸馏日期}-{三位流水号}`，如 `2026-08-11-001`
- 六大类共用同一流水号，保证全局唯一、按时间可排序
- 跨会话按时间先后排序编号，同一会话内按对话顺序编号

## 🛠️ 工作流程（五步，缺一不可）
1. 📥 **通读**：完整读取全部对话，识别会话边界、主题与时间线
2. 🧹 **分拣**：按去噪规则逐条标记，剔除无效内容
3. 🔗 **合并**：识别重复信息，执行合并策略，汇总来源
4. 🗂️ **提炼**：按六大类归档，编写条目，分配日期流水号
5. ✅ **校验**：逐条对照原文做保真检查（见下）

## 落盘规范（distilled/ 独立可见层）

1. 精华档案写入 `<根>/distilled/{YYYY-MM-DD}.md`（按蒸馏日期命名，可追加；同一天多次蒸馏追加到同日文件，流水号接续）
2. 更新 `<根>/distilled/manifest.json`：
   ```json
   { "lastRun": "2026-08-11T14:00:00+08:00", "eventsAtRun": 2215, "files": ["2026-08-11.md"] }
   ```
3. **蒸馏后隐藏**：被蒸馏覆盖的旧 `memories/` 条目 → 状态改 `🕰️过去`，frontmatter 追加 `superseded_by: distilled/2026-08-11.md`（列出清单，向用户确认后批量执行；**不删除任何文件**）
4. `events.db` 原始事件：**永远不动**（逐字铁律）
5. 检索：`memory-cli.js search` 默认只出可见层（🟢 + distilled 档案按需读入）；查历史用 `--include-past` 或直接读 `distilled/` 文件

## CONTEXT.md 回流（蒸馏后必做）

1. 蒸馏产出的「📖 术语与定义」→ 写入真源 `<真源根>/.context/CONTEXT.md`（即 cosmic-phantom 根目录 .context，F11 守卫检查对象；有同术语则合并定义并注明来源，新术语追加）——注意：不是具体项目工作区（项目工作区可能没有 .context；回流目标错位会导致内容静默丢失）
2. 蒸馏产出的「⚖️ 关键决策」→ 无需手写 ADR 文件（ADR 机制已废除，用户 2026-08-12 决定）；决策由决策卡同步器（decision-cards.js 自动管道）从 daily 逐字承载
3. 回流后向用户汇报：CONTEXT.md 新增/修改了哪些术语

## ✅ 质量校验清单（输出前逐项自检）
- [ ] 每条精华都能在原文找到明确出处，无虚构、无脑补
- [ ] 无寒暄/跑题/废案残留
- [ ] 重复信息已合并且来源完整
- [ ] 矛盾信息已归入 ❓ 且未擅自删改
- [ ] 编号无重复、无跳号，日期正确
- [ ] 去噪率如实计算：`去噪率 = 剔除条数 ÷ 原始总条数 × 100%`
- [ ] events.db / daily 蒸馏前后哈希零变化（只读断言）
- [ ] 待办/遗留条目已标注📅快照时间（蒸馏时刻或 eventsAtRun 对应时间）

## 失败处理与边界

- 模型调用失败 → 本次跳过，记 `<根>/hook-errors.log`，不重试轰炸，下周收工再试；已写文件保留可查，manifest 不更新
- 任何异常可见（日志），禁止静默吞错
- ❌ 不删除/不覆盖 events.db 与 daily（逐字铁律）
- ❌ 不做实时/每日蒸馏（每周批量 + 手动）
- ❌ 不做后台服务、不做定时器、不做开机自启（事件驱动铁律）
- ❌ 不自动删除旧条目文件（只改状态 🕰️ + superseded_by，且先经用户确认）
