# 🧭 CP 四段工作流（拷问 → 规格 → 票据 → 实施）

> 自包含：把本目录复制到任意宿主 skills 目录即可用；`<根>` = Cosmic Phantom 根（默认 `~/.cosmic-phantom`）。
> 细则真源：`<根>/core/workflow.md`；提问细则：`<根>/core/requirement-clarify.md`；硬纪律：`<根>/core/rules.md` §4.18。

## 🎯 何时用

- 用户说：写规格、出方案、拆票、排期、开工、看前沿、收口、结案、按流程走。
- 任务 ≥4 个文件、跨会话、跨模块，或需要先定架构再写代码。
- 已有一段确认过的需求对话，需要落成可执行规格。

**不用**：≤1 文件且 ≤30 分钟的改动；纯问答；探索性原型（标 `prototype`，不合并主干）。

## 🚦 第一步：判规模

| 规模 | 判据 | 走法 |
|---|---|---|
| 微 | ≤1 文件且 ≤30 分钟 | 直接做，收尾记 daily |
| 小 | 2-3 文件 | 一页 spec（问题/方案/测试决策）→ 实施 |
| 中 | ≥4 文件或跨会话 | spec + tickets（≥2 张） |
| 大 | 跨天/跨模块 | spec + tickets + 分阶段验收，可拆多个 work 项 |

判断不了按"中"走；不要为一行改动建 spec。

## ① 拷问（Grill）

- 小需求：一次 1-2 问，每题给 2-3 选项 + 推荐 + 理由。
- 大设计（≥3 个相互依赖决策）：**设计树 + 前沿轮**——一轮问完整个前沿，每题编号 + 推荐；用户答完再算下一轮；前沿为空才结束。
- **事实自己查**（读文件、跑命令、检索记忆），不向用户要；只有决策交给用户。
- 术语冲突当场指出；共识立即写回 `<根>/.context/CONTEXT.md`。
- 难逆决策进决策卡，**不建 ADR**（用户 2026-08-12 已拍板）。

## ② 规格（Spec）

```text
node <根>/work.cjs new <slug> --title "<标题>" --source "<会话/事件指针>"
```

七段必填：问题 / 方案 / 用户故事 / 实现决策 / 测试决策 / 范围外 / 来源证据（备注可选）。

- 问题与方案写用户视角；**不写文件路径、不贴实现代码**（会过期）。
- 用户故事要长，覆盖所有使用面向。
- 测试决策**先定缝**：优先复用既有缝、取最高层、越少越好；写清每个缝能抓什么、漏什么。
- 范围外必须写。
- 来源证据写 `events.db:<instance>:<mid>` 或会话 id。
- 写完 `node <根>/work.cjs check <slug>`，过检后请用户批准。

## ③ 票据（Tickets）

```text
node <根>/work.cjs ticket <slug> "<标题>" [--blocked-by 00] [--seams a,b]
```

- **tracer bullet 垂直切片**：每张票穿透所有层、可独立演示；禁止水平分层票。
- 单票装进一个全新上下文窗口；预重构先做。
- 宽重构按 `expand → migrate（分批）→ contract` 排票。
- `blocked_by` 是硬依赖；无依赖写 `[]`；有环/悬空 `check` 直接红。
- 用 `node <根>/work.cjs status <slug>` 给用户看粒度与依赖，批准后开工。

## ④ 实施（Implement）

```text
node <根>/work.cjs frontier <slug>
```

- 只从前沿取票；开工改 `in_progress`，完成改 `done` 并填证据。
- 测试在预先约定的缝上；红→绿；重构留到复核。
- 定期跑单测/类型检查，全部完成后跑全量测试。
- **双轴复核**：Standards（rules + 坏味自查）与 Spec（是否忠实规格、有无范围蔓延）分开报，不合并排序。
- 证据按 §4.15：修复前红灯 + 修复后绿灯；纯新增用注入故障态代替红灯。

## 🏁 结案

```text
node <根>/work.cjs close <slug>
```

前置：`check` 通过 + 所有票 `done`。动作：spec 改 `implemented` → 生成 `<根>/pro/work-<slug>-<日期>.md` → 目录移入 `work/.closed/`。

`verify` 的 **F28** 会报：spec 缺段、票据图异常、`in_progress` >7 天、`draft` >14 天、全票 done 未 close >7 天。

## ⛔ 反模式（出现即返工）

- 规格写完才去问关键问题。
- 按层切票（schema 票 / API 票 / UI 票）。
- 票 done 但证据是"已实现/测试通过"这种无命令自述。
- 用 Todo 当票据真源，`work/` 空着。
- 规格里塞文件路径和代码片段。
- 为走流程给一行改动建 spec。

## 🔗 与 CP 其他机制

| 机制 | 关系 |
|---|---|
| `CONTEXT.md` | 术语唯一真源，spec 用词必须一致 |
| 决策卡 | 难逆决策载体；spec 引用 id |
| Todo / TaskCreate | 只投影"今天要做的票"，work 才是真源 |
| `current-state.json` | 记"当前 work 项 + 下一张票" |
| `wrap-up.cjs` | 不因在制品阻塞；F28 stale 必须处置 |
| `pro/` | 结案档案；work 是在制，不混 |
