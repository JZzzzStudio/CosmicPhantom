# 🗣️ 说人话（plain-language）

> 由来：2026-11-19 用户原话"以后不是人话我一律不看"。此前同一份待办用术语写出去，用户读不懂；改成日常口语后，用户当场认可。
> 目标：让**不看代码的人**读完就知道"现在什么情况、下一步做什么、为什么"。

## 三条铁律

1. **一句一件事**：一个句子只说一个意思。要并列就分行，别用长从句套三层。
2. **术语必须先翻**：每个机制名 / 缩写 / 文件名第一次出现时，先用日常话解释它是干嘛的，再决定要不要保留原名。
3. **数字要能对上**：说"提升/下降"必须给两个数（改前、改后）和范围（多少题、哪一层）。说不出范围就别报数。

## 术语对照表（左边一律换成右边，或先解释再提）

| 别这样写 | 这样写 |
|---|---|
| 口径 | 怎么算、怎么报 |
| 粒度 | 算到哪一层（整段对话 / 某一句话） |
| 基线 | 现在的对照成绩 |
| 回归 / 不降 | 没变差 |
| 闸 / gate | 检查项（它会拦住什么） |
| fail-open | 出问题时不把整个流程卡死 |
| provenance | 这个分数是谁跑的、用的哪份数据 |
| 幂等 | 跑两遍结果一样 |
| 降级 | 缺东西时退到能用的老办法 |
| 准入 | 够不够格进来 |
| 端到端 | 从头到尾真跑一遍 |
| 抽样 | 先拿一部分试 |
| 冻结 | 定死，不许悄悄改 |
| XX 率 | 一百次里有几次 |

## 句式规则

- **第一句给结论**，第二句给理由，第三句给下一步。不要把过程写在最前面。
- 用"你"和"我"，不用"本系统""该机制"。
- 主语是人或具体东西："它会把结果吞掉"，不写"结果存在被吞风险"。
- 禁止形容词堆砌：显著、全面、深度、赋能、闭环——一律删掉，换成发生了什么。
- 用箭头和冒号表达因果，不用"从而/进而/鉴于"。

## 自检三问（写完必过）

1. 把这段念给一个不写代码的人听，他能复述出"发生了什么"吗？
2. 每个术语都解释过了吗？没解释的能不能删？
3. 有没有哪句话是"听起来专业但没信息"？有就删。

## 真实样例（2026-11-19 同一件事的两种写法）

**❌ 装逼版**

> P0-29a：剔除 cat5 对抗类，主分与会话粒度分列，保证含 provenance 的同集可比性。

**✅ 人话版**

> 先把两类怪分从总分里拿掉：一类是"对话里根本没有答案"的题，另一类是"找对整段对话"的分数。以后报分数必须写清楚：跑了几道题、算到哪一层、谁跑的。

**❌ 装逼版**

> 该机制 fail-open，采样不足时返回 insufficient，避免假绿。

**✅ 人话版**

> 东西没准备好时，它不会硬编一个答案，会直接说"证据不够"。这样我们就不会把"没查"当成"查过没问题"。

## 例外（保持原样，不要翻译）

- 代码、命令、路径、配置项、日志、报错原文
- 用户明确指定的格式（表格、JSON、清单模板）
- 专有名词首次出现后，后续可沿用原名（但第一次必须解释）

## 反面清单（出现即改）

显著 / 全面 / 深度 / 闭环 / 赋能 / 端到端能力 / 设计感 / 体系化 / 抓手 / 心智 / 抽象层 / 范式 / 颗粒度 / 复盘一下（当空话用时）

> 例外：这些词在**引用用户原话**或**引用已有文档标题**时可以保留，但要标出来源。
